# EBBLESS on Google Play (#562)

The Android app is a **Trusted Web Activity (TWA)**: a thin Play Store shell
that opens https://malgriot.github.io/EBBLESS/ full screen in Chrome. It has no
separate codebase. Every push to `main` that updates the site also updates the
Android app. A new Play build is only needed when the shell itself changes
(name, icon, version, package settings).

## What's already set up

| Piece | Where |
|---|---|
| Android project (generated by Bubblewrap) | `android/` |
| Package name (permanent once uploaded) | `io.github.malgriot.ebbless` |
| Upload signing key | `~/.ebbless-android/upload-keystore.p12` (alias `upload`) |
| Its password | `~/.ebbless-android/keystore-password.txt` |
| Domain proof (asset links) | [MalGriot/malgriot.github.io](https://github.com/MalGriot/malgriot.github.io), served at https://malgriot.github.io/.well-known/assetlinks.json |
| Build | `.github/workflows/android.yml` builds a signed `.aab` (for Play) and `.apk` (for sideloading) |

The key files never go in git. **Back up `~/.ebbless-android/`** somewhere safe
(a password manager or encrypted drive). If it's lost, Play support can reset
the upload key, but it takes days.

## Sideload APK (live now)

Every signed build is published to the `android` GitHub Release at a fixed URL,
linked from the beta page:
https://github.com/MalGriot/EBBLESS/releases/download/android/ebbless.apk

No Play account, review, or 14-day wait. Testers tap the link on their Android
phone and allow installs from their browser when asked. To ship a new APK, push
a change under `android/` or run `gh workflow run android.yml`. The release is
never marked latest, so `releases/latest` stays the Mac app.

## Step by step (Play Store, later)

### 1. Play Console account (you)

1. Go to https://play.google.com/console/signup and create a **personal**
   developer account. One-time $25 fee, plus ID verification (can take a few days).
2. Once approved: **Create app** > name `EBBLESS`, default language English,
   **App**, **Free**. Accept the declarations.

### 2. Give the build its signing key (run once, from the EBBLESS folder)

```bash
base64 -i ~/.ebbless-android/upload-keystore.p12 | gh secret set ANDROID_KEYSTORE_B64 --repo MalGriot/EBBLESS
```

```bash
gh secret set ANDROID_KEYSTORE_PASSWORD --repo MalGriot/EBBLESS < ~/.ebbless-android/keystore-password.txt
```

### 3. Build

```bash
gh workflow run android.yml --repo MalGriot/EBBLESS
```

When it finishes (about 5 minutes), download the files:

```bash
gh run download --repo MalGriot/EBBLESS --name ebbless-android --dir ~/Downloads/ebbless-android
```

You get `ebbless-1.0.0.aab` (upload this to Play) and `ebbless-1.0.0.apk`
(install directly on an Android phone to try it before Play is ready).

### 4. First internal test release

1. Play Console > your app > **Test and release > Testing > Internal testing**.
2. **Testers** tab: create an email list, add testers' Gmail addresses, save.
3. **Create new release**. When asked about app signing, keep
   **Google-generated key** (Play App Signing). Upload the `.aab`.
   Release name: `1.0.0`. Notes: anything short. **Save > Review release > Start rollout**.
4. Back on the **Testers** tab, copy the **opt-in link** and send it to testers.
   They open it on their Android phone, accept, then install from Play.

Internal testing has no review wait and takes up to 100 testers.

### 5. Add Play's signing key to the domain proof (important)

Play re-signs the app with its own key, so the asset links file needs that
fingerprint too. Without it, testers who install from Play see a browser URL
bar at the top of the app.

1. Play Console > **Test and release > App integrity > Play app signing**.
2. Copy the **App signing key certificate** SHA-256 fingerprint.
3. Paste it to Claude, or add it yourself to `.well-known/assetlinks.json` in
   the `malgriot.github.io` repo as a second entry in
   `sha256_cert_fingerprints`. Keep the existing upload key entry.

### 6. Forms Play will ask for (App content)

Play blocks some releases until these are filled in under **Policy and
programs > App content**: privacy policy URL, ads (EBBLESS shows none of its
own), app access (no login needed), content rating questionnaire, target
audience, data safety. **EBBLESS does not have a privacy policy page yet** and
Play requires one, so that needs to be written and published on the site.

## Updating the app shell later

Only needed when changing name, icon, colors, or package settings, not for
normal site updates.

1. Bump `appVersionCode` (+1) and `appVersionName` in `android/twa-manifest.json`,
   and the matching `versionCode` / `versionName` in `android/app/build.gradle`.
2. Push to `main`. The workflow builds automatically.
3. Download the new `.aab` and upload it as a new internal testing release.

## Going public later

New personal accounts must run a **closed test with at least 12 testers
opted in for 14 days in a row** before production access is granted. Move
testers from internal to a closed track when ready to start that clock.

## Policy risk to keep in mind

Ad avoidance (#523) mutes and skips ads in third-party players. Play policy
prohibits apps that interfere with other apps' or services' ads, so a reviewer
could reject a production release over it. Internal testing gets little or no
review, so this mostly matters at the closed-test and production stages.
